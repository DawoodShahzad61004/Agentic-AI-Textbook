1. Docling — my first recommendation

Docling is probably the best starting point for your system.

It supports:

PDF
DOCX
PPTX
XLSX
HTML
EPUB
Images
EML and MSG
LaTeX
Audio formats and WebVTT

Its major advantage is not merely extracting text. It attempts to preserve:

Page layout
Headings and hierarchy
Reading order
Tables and table structure
Formulas
Code blocks
Images and captions
Document metadata

It produces a unified DoclingDocument, which can then be exported to Markdown, JSON or text. It also provides native chunkers and integrations with LangChain and LlamaIndex. Official documentation

from docling.document_converter import DocumentConverter

converter = DocumentConverter()
result = converter.convert("document.pdf")

markdown = result.document.export_to_markdown()

For Memora, Docling would be a strong primary parser because your retrieval quality depends heavily on maintaining document structure.

2. Unstructured

Unstructured is one of the most established document-ingestion libraries in the RAG ecosystem.

It divides documents into typed elements such as:

Title
NarrativeText
ListItem
Table
Image
Header
Footer

Example:

from unstructured.partition.auto import partition

elements = partition(filename="document.pdf")

for element in elements:
    print(type(element).__name__, element.text)

Strengths:

Automatic file-type detection
Many supported formats
OCR and layout-aware PDF strategies
Element-based metadata
Built-in chunking strategies
Easy LangChain integration

Weaknesses:

Installation can be dependency-heavy.
Advanced PDF processing is slower than basic extraction.
Behavior varies significantly between fast, hi_res, and OCR strategies.
Some capabilities marketed by the company belong to hosted products rather than the core open-source package.

Use it when you need a mature ingestion framework with configurable partitioning and chunking. Open-source overview

3. Apache Tika

Apache Tika supports text and metadata extraction from more than a thousand file types through a single interface.

It handles formats including:

PDF
Microsoft Office
OpenDocument
RTF
EPUB
HTML and XML
Images
Archives
Email
Audio and video metadata
Legacy document formats

Strengths:

Extremely broad format coverage
Stable and mature
Good MIME-type detection
Excellent metadata extraction
Useful as a fallback parser

Limitations:

It primarily extracts content, rather than reconstructing complex layout.
Tables, multi-column PDFs, formulas and visual hierarchy may be flattened.
It is Java-based, although you can run it as a server and call it from Python.

Tika is best used as a universal fallback, not necessarily as the primary complex-PDF parser. Supported formats

4. LlamaIndex Readers

LlamaIndex Readers provide a common loader interface for local files and external sources.

from llama_index.core import SimpleDirectoryReader

documents = SimpleDirectoryReader(
    input_dir="./documents",
    recursive=True
).load_data()

SimpleDirectoryReader supports common formats such as PDF, DOCX, PPT/PPTX, EPUB, images, notebooks, CSV and Markdown. SimpleDirectoryReader documentation

Important distinction: LlamaIndex Readers are orchestration adapters. They often delegate parsing to packages such as pypdf, Docling or Unstructured. Therefore, using a LlamaIndex Reader does not automatically guarantee strong table or layout extraction.

5. LangChain Document Loaders

Because you already use LangChain and LangGraph, these are operationally convenient:

DirectoryLoader
PyPDFLoader
PyMuPDFLoader
UnstructuredFileLoader
UnstructuredPDFLoader
DoclingLoader
MicrosoftWordLoader
UnstructuredPowerPointLoader
CSVLoader
JSONLoader

Example with Docling:

from langchain_docling import DoclingLoader

loader = DoclingLoader(file_path=["report.pdf", "notes.docx"])
documents = loader.load()

LangChain loaders normalize parser output into LangChain Document objects. They are wrappers rather than one universal parsing engine. For example, DoclingLoader obtains its layout and table understanding from Docling.

6. Marker

Marker is particularly useful for complex PDFs involving:

Multiple columns
Tables
Mathematical equations
Code
Images
Headers and footers
Scientific-paper layouts

It generally targets high-quality Markdown or structured output. It can be computationally heavier than basic parsers and may benefit substantially from GPU acceleration.

Use Marker when Markdown fidelity is more important than supporting hundreds of unrelated formats.

7. MinerU

MinerU specializes in converting complex PDFs into machine-readable representations.

It is especially suitable for:

Research papers
Technical documents
Equations
Tables
Multi-column layouts
Scanned or mixed-content PDFs

It is a specialized PDF parser rather than a universal loader. Deployment and model dependencies are also heavier than libraries such as PyMuPDF.

8. PyMuPDF4LLM

PyMuPDF4LLM provides fast PDF extraction designed for LLM and RAG workflows.

import pymupdf4llm

markdown = pymupdf4llm.to_markdown("document.pdf")

It offers a good balance between speed and structure preservation. However, for extremely complicated tables, equations or scanned pages, Docling, Marker or MinerU will generally be safer choices.

Production recommendation for Memora

I would use a routed ingestion architecture:

My shortlist would be:

Docling as the primary multi-format parser.
PyMuPDF4LLM as the fast path for ordinary digital PDFs.
PaddleOCR or OCRmyPDF for scanned documents.
Apache Tika as the broad-format fallback.
LangChain loaders as adapters that expose all output as LangChain Document objects.

Avoid relying on a single parser in production. File extensions do not reveal whether a PDF is scanned, encrypted, malformed, multi-column or table-heavy. A production pipeline should inspect each file, select an appropriate parser, preserve page and section metadata, and quarantine low-confidence parsing results.

def elements_to_markdown(elements):
    lines = []
    for el in elements:
        category = el.category
        text = str(el)
        if category == "Title":
            lines.append(f"# {text}")
        elif category == "Header":
            lines.append(f"## {text}")
        elif category == "ListItem":
            lines.append(f"- {text}")
        else:
            lines.append(text)
    return "\n\n".join(lines)
