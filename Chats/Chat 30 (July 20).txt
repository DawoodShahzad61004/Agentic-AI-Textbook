Splitting rules implemented in temp_split() (chunking/ingest.py)
Core parameters

CHUNK_SIZE = 1600 chars — soft/hard limit for prose, but tables and list "pointers" are treated as indivisible and can exceed it.
MIN_CHUNK_CHARS = 50 — chunks shorter than this are dropped in split_documents().
Structural detection (pre-pass, done once per document)

Fenced code blocks (``` / ~~~) are detected first and excluded from heading/table matching, so headings or table-like lines inside code fences are ignored.
Headings = ATX #–###### lines outside code fences, recorded with their level.
Tables = GitHub-style pipe tables (header row + separator row of -/:-/-:/:-: cells, followed by consecutive row lines), outside code fences.
Lists = blocks (paragraph-delimited by blank lines) whose first line is a -/*/+/N./N) item; indentation is tab-expanded to measure nesting depth.
Whole-block protection rules (checked at the top of the main loop, in order)

Heading(s) immediately before a table → the whole consecutive heading run plus the table is emitted as one chunk (prevents a heading-only chunk stranded before an oversized table).
Table reaches the cursor → the entire table is emitted as one chunk regardless of size (tables are never split).
Paragraph immediately before a flat list → the lead-in paragraph (e.g. "To be submitted in accordance with:") is kept with the list. If it fits in CHUNK_SIZE it's one chunk; if oversized, the paragraph+first item become one chunk and each remaining item becomes its own chunk.
Heading immediately before a flat (single-indent-level) list, with nothing else in the section → heading+list kept together if it fits; if oversized, split one list item per chunk (heading attached to the first item).
Flat list starting exactly at the cursor → split one list item at a time, keeping any continuation lines with their item.
Size-limited cut rules (_structural_cut, applied when none of the above whole-block rules fire and the text exceeds CHUNK_SIZE)

Rule 2 — nested heading hierarchy in the candidate: if more than one heading falls inside the size window, find the deepest (numerically largest ATX # level) heading(s); drop all sections at that deepest level from the candidate (move them to the next chunk) unless doing so would produce an empty chunk, in which case only the final incomplete peer section is moved.
Rule 3(i) — heading right after the limit: if a heading starts right where the size limit falls, that boundary is already safe and is used as-is.
Rule 3(ii), lists — limit lands inside a list:
If the enclosing list is flat (one indent level), move the whole list forward (to a preceding lead-in paragraph if present, otherwise to the list start) so it can be split per-item on the next loop iteration.
If the list has mixed indentation, move only the deepest-nested item(s) forward, keeping shallower items in the current chunk.
Rule 3(ii), prose — limit lands in plain text: cut at the start of the last complete paragraph before the limit (paragraph = blank-line-delimited block), so no chunk ends mid-paragraph.
Hard-cut fallback: if a single paragraph/heading itself exceeds CHUNK_SIZE (no paragraph boundary to use), cut at the nearest newline, else nearest space/tab, else exactly at the limit — guaranteeing the loop always advances.
Rules 4 & 5 — partial table inside the size window: if a table would be split by the size limit, exclude it entirely from the current chunk and roll it into the next one. If the current chunk started with a heading (or heading group), that heading group is carried forward with the table too, unless there's a closer heading between the start and the table, in which case only the table is deferred and the closer heading is kept as the boundary.
Post-cut cleanup

Trailing-heading rollover: if the chosen cut point leaves a heading as the last non-blank line of a chunk (with no body content after it), the cut is pulled back to before that heading so a chunk never ends on a bare heading.
Heading-only fallback (_cut_with_heading_content): if the computed cut would produce a chunk containing only heading lines (no body text), extend the cut to include content following the initial heading group — cutting at a newline within that content, or a space/tab if no newline is available before the limit.
Rollover check runs a second time on the final cut candidate in case the heading-content fallback itself lands right after a later heading.
Chunk emission: leading/trailing blank lines/\r\n are stripped; empty results are discarded (_append_chunk).
Per-item hard-splitting (_append_limited): used when emitting individual list items — if a single item still exceeds CHUNK_SIZE, it's hard-cut via the same newline→space→limit fallback as above.
Bookkeeping

Files under 1 char after .strip() produce no chunks.
Each chunk gets a zero-based chunk_seq per source file, assigned after all splitting (split_documents).
Net effect: tables are always atomic; flat lists are split one item at a time (never mid-item) with lead-in paragraphs/headings preserved; nested-heading sections are peeled off by depth rather than mid-sentence; plain prose falls back to paragraph boundaries, then word boundaries, as a last resort; and no chunk is ever allowed to end on a lone heading.
