Failure type

Answer-generation lesson

Yes. Several open-source frameworks provide agent-memory management, but none will automatically solve all your correctness, validation, conflict, and obsolescence problems.

For your existing LangGraph + ChromaDB + MongoDB architecture, LangMem is the best first tool to evaluate.

Tool	Primary strength	Fit for your project
LangMem	Extracting, consolidating and updating long-term memories	Best fit—native LangGraph integration and usable with your existing storage
Mem0	Drop-in persistent memory and personalization	Good if you want a more complete standalone memory layer
Graphiti	Temporal knowledge graphs, changing facts and relationships	Strong for conflicts, supersession and time-aware knowledge
Cognee	Combined vector and knowledge-graph memory	Useful when relationships and multi-hop retrieval matter
Letta	Full stateful-agent runtime inspired by MemGPT	Powerful, but likely requires too much architectural change
LangGraph Store	Namespaced cross-thread persistence	Foundational storage mechanism—not a complete memory lifecycle manager
My recommendation for your system
1. Use LangMem as a toolkit, not as the owner of everything

LangMem provides:

memory extraction from interactions;
consolidation and deduplication;
semantic memory;
procedural memory;
background memory processing;
native LangGraph Store integration.

Its functional primitives can also work with other storage systems, so you would not necessarily need to abandon MongoDB or ChromaDB. LangMem documentation

Possible mapping:

Your data	Memory type
documents	Authoritative semantic knowledge/RAG corpus
learned_qa	Derived semantic or episodic memory
failure_lessons	Negative procedural memory
feedback_interactions	Raw episodic/audit records
user_thumbdowns	Negative feedback events
LangGraph checkpoints	Short-term conversational state

However, you would still need to implement your own:

claim-to-evidence validation;
candidate/active/disputed lifecycle;
source authority;
document versioning;
conflict-resolution policy;
provenance;
ranking and aging rules.
2. Consider Graphiti only if temporal conflicts become central

Graphiti models entities, relationships and facts with temporal validity. It can invalidate older facts as circumstances change and retrieves through vector search, full-text search and graph traversal. Graphiti overview

It becomes valuable for memories such as:

User prefers X
User later changes preference to Y
Software version 2 replaces version 1 behavior
Policy B supersedes policy A

For your current document-QA pipeline, introducing Neo4j or another graph database may be excessive unless you genuinely need entity relationships and time-aware fact evolution.

3. Mem0 is the best “memory service” alternative

Mem0 provides extraction, storage, updating, consolidation and semantic retrieval behind a relatively small API. Its open-source version can run on your infrastructure, and it has a LangGraph integration. Mem0 OSS overview, LangGraph integration

It is attractive if you want:

memory.add(interaction, user_id=...)
memory.search(query, user_id=...)

But adopting it could duplicate or replace parts of your current learned_qa pipeline. You should first test whether its extraction and update rules preserve the strict evidential grounding your domain requires.

Practical conclusion

Do not replace your entire architecture immediately.

Run a small proof of concept:

Keep MongoDB as the authoritative audit and metadata store.
Keep your document collection separate.
Use LangMem to generate and consolidate candidate learned_qa and failure_lessons.
Pass every candidate through your own hybrid heuristic + LLM validator.
Compare retrieval quality, memory duplication, latency and token usage against your existing pipeline.

Your likely production architecture is:

LangGraph checkpoints  → short-term state
MongoDB                → canonical memory records and audit history
Vector index           → semantic retrieval
LangMem                → extraction and consolidation
Your validation layer  → admission, conflicts, provenance and lifecycle

So yes, an open-source library can save substantial implementation work—but memory storage/retrieval is the easy part. For your project, the difficult and application-specific part remains deciding what deserves to become memory, when it becomes invalid, and which evidence should override it.

10. Priority and aging proposal

Your original proposal was:

On ingestion/distillation:             100
After each interaction, not retrieved:  -1
Retrieved with no redundancy:          +10
Retrieved with redundancy:              +2

You also proposed making old memories obsolete after a fixed number of interactions.

Problems identified
Unrelated traffic causes false decay

An ASD memory should not lose priority because users ask hundreds of unrelated engineering questions.

A memory should only be penalized after a relevant retrieval opportunity.

Retrieval does not prove usefulness

A generic or poisoned memory may be retrieved frequently. Rewarding retrieval alone can strengthen bad memories.

Rich-get-richer feedback loop

A high-priority memory gets retrieved more, gains more priority, and further suppresses new memories.

Redundancy should not receive a meaningful reward

A redundant chunk consumed context without adding unique information.

One score mixes unrelated concepts

Correctness, relevance, authority, freshness, utility, and feedback should not be compressed into one mutable counter.

Revised signals

Maintain separate values:

semantic_relevance
authority
validation_confidence
freshness
utility
feedback
novelty
conflict_penalty

Then calculate query-time ranking:

rank =
    semantic_relevance
    × trust_factor
    × freshness_factor
    + bounded_utility_boost
    + novelty_boost
    - conflict_penalty

Historical use should be bounded, for example:

usage_boost =
    min(MAX_USAGE_BOOST, log1p(successful_uses) × weight)

Suggested event effects:

Validated unique contribution: positive
Relevant but redundant: zero or very small positive
Irrelevant retrieval: negative
Contradicted or thumbed down: strong negative and mark disputed
Not retrieved for an unrelated query: no change
Eligible but repeatedly unused: limited decay

Priority should primarily affect retrieval order, not cause immediate deletion.

Suggested lifecycle:

active → cold → archived

Hard deletion should normally be reserved for:

Exact duplicates
Confirmed corruption
Privacy deletion
Retention-policy expiry
11. Time and obsolescence

We concluded that a universal “obsolete after F interactions” rule is inappropriate.

Different memories age differently:

Software APIs and prices: quickly
Laws and policies: according to effective dates
Scientific findings: according to source/version changes
Historical facts: may never become stale
User preferences: can change unpredictably
Document-derived knowledge: becomes stale when its supporting version is superseded

Freshness should therefore be based on memory type, domain, source version, and real-world validity—not global interaction count.

What can u tell me about LangMem
Worked for 32s

LangMem is an open-source Python library from LangChain for giving agents structured, persistent memory. The simplest description is:

LangGraph Store saves and retrieves memories; LangMem decides what should become a memory and how existing memories should change.

It is not a database, vector database, or complete memory platform by itself.

What LangMem does

LangMem can examine conversations or agent trajectories and:

Extract durable facts, preferences, goals, and other useful information.
Convert extracted information into structured Pydantic objects.
Create, update, and optionally delete existing memories.
Consolidate new information with previously stored memories.
Give an agent tools to explicitly save and search memories.
Summarize long conversation histories.
Improve system prompts using previous conversations and feedback.

The official project describes three broad memory categories:

Memory type	Meaning	Example
Semantic	Facts and knowledge	“The user is learning Agentic AI.”
Episodic	Previous experiences	“A previous retrieval strategy failed for table questions.”
Procedural	Instructions or learned behavior	“Always validate retrieved chunks before answering.”

LangMem conceptual guide

The two main memory-writing approaches
1. Hot-path memory

The agent receives memory tools and consciously decides during the conversation whether to save, modify, delete, or search memory.

LangMem provides tools such as:

create_manage_memory_tool
create_search_memory_tool

This is useful when the information must become available immediately. However, it adds tool calls, latency, and more responsibility to the main agent.

2. Background memory

The response is generated normally, while a separate memory process later reviews the conversation and extracts or consolidates useful information.

The important primitive here is:

create_memory_store_manager(...)

This is generally the better production pattern for automatic memory because memory processing does not slow down every user response. It also lets you batch, audit, validate, and retry memory extraction independently. LangMem background guide

There is also:

create_memory_manager(...)

This produces structured extracted memories without requiring LangGraph Store to be the final storage mechanism. Therefore, you can connect it to your own MongoDB, ChromaDB, PostgreSQL, or custom repository layer. Memory API

LangMem versus LangGraph Store

This distinction is extremely important:

LangMem	LangGraph Store
Memory-processing logic	Storage and retrieval abstraction
Extracts useful information	Persists JSON documents
Consolidates or updates memories	Organizes data by namespace and key
Can generate structured memories	Can optionally perform semantic search
Uses an LLM	Does not inherently decide what is worth remembering

A typical arrangement is:

LangGraph distinguishes its store from a checkpointer:

A checkpointer retains the state of one conversation/thread.
A store retains application or user knowledge across different threads.

final=semantic_score×(floor+(1−floor)e
−λ⋅age
)

LangMem does not automatically convert feedback_interactions into learned_qa and failure_lessons.

Those are concepts from your architecture, not built-in LangMem collection types. You must define exactly what LangMem should extract and write the ChromaDB integration yourself.

Your current learned_qa transformation

Your existing SelfLearner currently performs approximately this pipeline:

For example, a raw record such as:

{
  "request_id": "req-123",
  "query": "What is Neighbor-Aware Compression?",
  "answer": "NAC joins consecutive chunks from the same source...",
  "quality": "OK",
  "document_chunks": [...],
  "learned_qa_chunks": [...]
}

might become:

{
  "question": "How does Neighbor-Aware Compression work?",
  "answer": "It reconnects adjacent chunks from the same source before later compression stages.",
  "source_request_id": "req-123"
}

The question and answer are serialized, embedded using all-MiniLM-L6-v2, and inserted into learned_qa.

This currently happens through your custom SelfLearner, not LangMem.

What LangMem would actually do

You would define a schema such as:

class LearnedQA(BaseModel):
    question: str
    answer: str
    source_request_ids: list[str]
    confidence: float
    created_at: datetime
    updated_at: datetime

Then configure:

learned_qa_manager = create_memory_manager(
    llm,
    schemas=[LearnedQA],
    instructions="""
    Extract reusable, self-contained question-answer knowledge only from
    successful and validated interactions.

    Preserve verified facts from the supplied evidence.
    Merge semantically duplicate memories.
    Do not extract unsupported claims.
    """
)

You convert the MongoDB record into messages/input:

messages = [
    {
        "role": "user",
        "content": interaction["query"],
    },
    {
        "role": "assistant",
        "content": interaction["answer"],
    },
]

LangMem sends the following to an LLM:

Your schema
Your extraction instructions
The interaction
Optionally, relevant existing memories

The LLM then proposes operations conceptually equivalent to:

Insert a new LearnedQA
Update an existing LearnedQA
Leave an existing memory unchanged
Delete one, if deletion is enabled

The core create_memory_manager() returns structured ExtractedMemory objects. It does not embed them or write them to Chroma. Your adapter must serialize, embed and upsert them. This database-independent transformation behavior is how LangMem’s core API is designed. LangMem Memory API

A thumbdown should not be transformed using the same schema or prompt.

For example:

class FailureLesson(BaseModel):
    trigger_query: str
    failed_approach: str
    failure_reason: str
    corrective_action: str
    bad_answer_excerpt: str | None
    source_request_ids: list[str]
    confidence: float
    created_at: datetime
    updated_at: datetime

Input evidence should combine the two MongoDB records:

feedback_interactions
    request_id
    query
    rejected answer
    retrieved evidence
    variants
            +
user_thumbdowns
    request_id
    explicit user feedback

LangMem could produce:

{
  "trigger_query": "Explain cyclic execution in Langflow",
  "failed_approach": "Treated a static graph edge as an interactive input loop",
  "failure_reason": "The flow reruns nodes but does not reopen the playground input",
  "corrective_action": "Use an external invocation loop or API client for repeated input",
  "bad_answer_excerpt": null,
  "source_request_ids": ["req-456"],
  "confidence": 0.94
}

Your adapter would then:

Serialize the lesson into retrieval-friendly text.
Generate its embedding.
Upsert it into failure_lessons.

Compared with your current one-way distillation, LangMem can receive relevant existing memories alongside the new interaction:

result = manager.invoke({

})

Add a genuinely new memory.
Merge repeated observations.
Update an older lesson.
Consolidate multiple related records.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

This is an evaluation sandbox, not a product. Its only job is to help decide which external memory-management
library should replace/augment the hand-rolled memory layer currently used by the main project, **Memora**
(sibling directory `../RAG-work`, a self-learning agentic RAG system).

The approach: build a small, throwaway memory setup with one candidate library at a time — currently starting
with **LangMem** — that mimics the memory behavior Memora actually needs, then compare candidates against each
other and against Memora's existing custom implementation.

## Repository Structure

Each memory system under evaluation gets its own top-level directory (e.g. `LangMem/`). Expect siblings like
`Mem0/`, `Letta/`, etc. to be added the same way as evaluation moves to the next candidate. Directories are
independent experiments — don't assume shared code or a common harness between them unless one is explicitly
introduced.

The environment is currently a bare `uv`-managed venv (Python 3.13, `.venv/`) with no dependencies installed and
no `pyproject.toml`/`requirements.txt` yet — those get added per-candidate as each library is wired in. Use `uv`
(not raw `pip`/`venv`) for environment and dependency management, consistent with how the sibling project manages
its own environment.

## What "similar to my original one" means

The reference point for every experiment here is Memora's memory architecture (see
`../RAG-work/docs/Architecture.md`, "Memory Architecture" section), which separates memory into four layers:

- **Working memory** — the live LLM context window (system prompt + conversation + compressed retrieved chunks).
- **Semantic memory** — source documents, embedded and stored once, read-only at query time.
- **Episodic / learned memory** — distilled Q&A pairs written back after successful interactions, retrieved
  independently from source documents and given precedence on conflict.
- **Failure memory** — records of bad answers/failed query variants, injected back into future prompts to steer
  the agent away from repeating them.

When building a candidate's temp/toy setup in this repo, model these same four roles (or the ones relevant to
the candidate library's design) rather than an arbitrary demo — the goal is a like-for-like comparison, e.g. "how
does LangMem's memory-store abstraction handle the episodic-write + precedence-on-conflict behavior Memora's
custom `learned_qa` collection currently provides?"

## Working with the sibling project

`../RAG-work` is read-only reference material for this repo — never edit it from here. Read its `README.md` and
`docs/Architecture.md` to understand the current memory behavior before designing a new candidate's experiment;
`docs/Decisions.md` may also have ADRs relevant to why the current memory design looks the way it does. If
`../RAG-work` isn't in this session's accessible directories yet, ask the user to grant access rather than
assuming its contents.

def build_graph():
    graph = StateGraph(GraphState)

    # ── Entry point ───────────────────────────────────────────────────────────
    graph.add_node("user_input", user_input_node)

    # ── Command nodes (each terminates at END) ────────────────────────────────
    graph.add_node("cmd_stats", cmd_stats)
    graph.add_node("cmd_learn", cmd_learn)
    graph.add_node("cmd_bad", cmd_bad)
    graph.add_node("cmd_exit", cmd_exit)

    # ── Query variant generation ──────────────────────────────────────────────
    graph.add_node("generate_query_variants", generate_query_variants)

    # ── Parallel retrieval ────────────────────────────────────────────────────
    graph.add_node("retrieve", retrieve)

    # ── Post-retrieval filter (fan-in barrier after all retrieve branches) ────
    graph.add_node("post_retrieval_filter", post_retrieval_filter_node)

    # ── Per-track retrieval validation (parallel) ─────────────────────────────
    graph.add_node("validate_document_retrieval", validate_document_retrieval)
    graph.add_node("validate_learned_qa_retrieval", validate_learned_qa_retrieval)

    # ── Per-track dedup-merge (parallel) ──────────────────────────────────────
    graph.add_node("dedup_merge_documents", dedup_merge_documents)
    graph.add_node("dedup_merge_learned_qa", dedup_merge_learned_qa)

    # ── Per-track dedup-merge validation (parallel, always-present pass-throughs)
    graph.add_node("validate_dedup_merge_documents", validate_dedup_merge_documents)
    graph.add_node("validate_dedup_merge_learned_qa", validate_dedup_merge_learned_qa)

    # ── Document compression track (parallel with learned_qa track) ───────────
    # NAC → DC → LBC, each with an optional validation step.
    # validate_LBC_documents is always present (pass-through when validation is
    # disabled) to give combine_tracks a fixed set of two predecessors.
    graph.add_node("NAC_documents", execute_nac_documents)
    graph.add_node("validate_NAC_documents", validate_nac_documents)
    graph.add_node("DC_documents", execute_dc_documents)
    graph.add_node("validate_DC_documents", validate_dc_documents)
    graph.add_node("LBC_documents", execute_lbc_documents)
    graph.add_node("validate_LBC_documents", validate_lbc_documents)

    # ── Learned-QA compression track (parallel with documents track) ──────────
    # DC → LBC (no NAC), each with an optional validation step.
    # validate_LBC_learned_qa is always present for the same fan-in reason.
    graph.add_node("DC_learned_qa", execute_dc_learned_qa)

def _build_context(compressed_docs: list[dict]) -> str:

def generate_answer(state: GraphState, config=None) -> dict:
    _t0 = time.perf_counter()
    compressed_docs = state["compressed_docs"]
    user_input = state["user_input"]

    context = _build_context(compressed_docs)
    draft = state.get("draft")

    if draft:
        prompt = _GENERATE_ANSWER_FROM_DRAFT_PROMPT.format(
            query=user_input,
            context=context,
            draft=draft,
        )
        caller_tag = "GENERATE-ANSWER-FROM-DRAFT"
    else:
        prompt = _GENERATE_ANSWER_PROMPT.format(
            query=user_input,
            context=context
        )
        caller_tag = "GENERATE-ANSWER"

    logger.debug("[GENERATE_ANSWER] PROMPT:\n%s", prompt)
    result = llm_invoke(llm, [{"role": "user", "content": prompt}], caller_tag=caller_tag, config=config)
    if result.ok:
        answer = (result.content or "").strip()
    elif draft:
        # Final-synthesis call failed — fall back to the draft as-is rather than
        # returning nothing.
        logger.warning(
            "[GENERATE_ANSWER] final synthesis LLM call failed (%s) — falling back to draft",
            result.error_kind,
        )
        answer = draft
    else:
        logger.error(
            "[GENERATE_ANSWER] LLM call failed (%s): %s",
            result.error_kind, result.error_message,
        )
        answer = ""

    logger.debug("[GENERATE_ANSWER] RESPONSE:\n%s", answer)
    logger.info("Assistant: %s", answer)

    # Derive quality from the judge verdict so non-GROUNDED answers are logged correctly.
    verdict = (state.get("quality_verdict") or "").strip().upper()
    quality = "OK" if (not verdict or verdict == QUALITY_PASS_VERDICT) else verdict

    sources = [{"source": d.get("source", "?")} for d in compressed_docs]
    feedback_store.log(
        query=user_input,
        answer=answer,
        sources=sources,
        quality=quality,
        document_retrieved_chunks=state.get("compressed_document_chunks") or [],
        learned_qa_retrieved_chunks=state.get("compressed_learned_qa_chunks") or [],
        request_id=state.get("request_id", ""),
        variants=list(state.get("variants_with_chunks") or []),
    )

    # Persist zero-result query phrasings so future runs block them upfront.
    newly_failed = list(state.get("newly_failed_variants") or [])
    feedback_store.save_failed_variants(user_input, newly_failed)
    if newly_failed:
        logger.info(
            "[GENERATE_ANSWER] saved %d newly-failed variant(s) to failed_variants.json",
            len(newly_failed),
        )

    # Update session-level cache so cmd_bad can enrich the thumbdown entry.
    services.last_variants_with_chunks = list(state.get("variants_with_chunks") or [])

    timing_tracker.record("Final Generation", time.perf_counter() - _t0)
    return {"answer": answer}

def user_input_node(state: GraphState) -> dict:
    raw = (state["user_input"] or "").strip()
    raw_lower = raw.lower()
    if raw_lower in {"exit", "quit"}:
        return {"command": "exit"}
    if raw_lower == "stats":
        return {"command": "stats"}
    if raw_lower == "learn":
        return {"command": "learn"}
    if raw_lower == "bad":
        return {"command": "bad"}

    # Load blocked variants for this query (zero-result phrasings from prior runs)
    blocked_variants = feedback_store.load_failed_variants(raw)

    # Load prior thumbdowns (user-flagged bad answers for this query)
    prior_thumbdowns: list[dict] = feedback_store.find_thumbdowns_for_query(raw) or []

    # Expand blocked from thumbdown variant history — every reformulation that led
    # to a bad answer is also blocked, matching the agent_query.py pattern.
    existing_blocked: set[str] = set(blocked_variants)
    for td in prior_thumbdowns:
        for v in (td.get("variants") or []):
            vq = (v.get("query") or "").strip()
            if vq and vq not in existing_blocked:
                blocked_variants.append(vq)
                existing_blocked.add(vq)

    if blocked_variants:
        logger.debug(
            "[USER_INPUT] %d blocked variant(s) injected for query: %r",
            len(blocked_variants), raw,
        )
    if prior_thumbdowns:
        logger.debug(
            "[USER_INPUT] %d prior thumbdown record(s) found for query: %r",
            len(prior_thumbdowns), raw,
        )

    return {
        "command": "",
        "blocked_variants": blocked_variants,
        "prior_thumbdowns": prior_thumbdowns,
    }

class VectorStore:
    def __init__(
        self,
        collection_name: str = "documents",
        persist_directory: str = "../data/vector_store",
    ):
        self.collection_name = collection_name
        self.persist_directory = persist_directory
        self.client = None
        self.collection = None
        self._initialize_store()

    def _initialize_store(self):
        try:
            os.makedirs(self.persist_directory, exist_ok=True)
            self.client = chromadb.PersistentClient(path=self.persist_directory)
            self.collection = self.client.get_or_create_collection(
                name=self.collection_name,
                metadata={
                    "Description": "Collection of document embeddings for RAG system.",
                    "hnsw:space": "cosine",
                },
            )
            logger.info(f"Vector store initialized: collection='{self.collection_name}', path='{self.persist_directory}'")
            logger.info(f"Existing documents in collection: {self.collection.count()}")
        except Exception:
            logger.exception(f"Error initializing vector store '{self.collection_name}'")
            raise

    def _sanitize_metadata_value(self, value):
        if isinstance(value, (str, int, float, bool)) or value is None:
            return value
        if isinstance(value, list):
            return [
                item if isinstance(item, (str, int, float, bool)) or item is None
                else json.dumps(item, ensure_ascii=True)
                for item in value
            ]
        try:
            return json.dumps(value, ensure_ascii=True)
        except Exception:
            return str(value)

    def _sanitize_metadata(self, metadata: Dict[str, Any]) -> Dict[str, Any]:
        return {str(k): self._sanitize_metadata_value(v) for k, v in metadata.items()}

    def add_document(self, documents: List[Any], embeddings: np.ndarray):
        if len(documents) != len(embeddings):
            raise ValueError("Number of documents and embeddings must match.")
        logger.info(f"Adding {len(documents)} documents to the vector store...")

        ids, metadatas, documents_text, embeddings_list = [], [], [], []

        for i, (doc, embedding) in enumerate(zip(documents, embeddings)):
            ids.append(str(uuid.uuid4()) + f"_{i}")
            metadata = {**dict(doc.metadata), "doc_index": i, "content_length": len(doc.page_content)}
            metadatas.append(self._sanitize_metadata(metadata))
            documents_text.append(doc.page_content)
            embeddings_list.append(embedding.tolist())

        self.collection.add(
            ids=ids,
            embeddings=embeddings_list,
            metadatas=metadatas,
            documents=documents_text,
        )
        logger.info(f"{len(documents)} documents added to vector store.")

    def add_documents_in_batches(
        self,
        pdf_chunks,
        embedding_manager: EmbeddingManager,
        batch_size: int = 128,
    ):
        total = len(pdf_chunks)
        logger.info(f"Adding {total} chunks in batches of {batch_size}")

        for start in range(0, total, batch_size):
            end = min(start + batch_size, total)
            batch_docs = pdf_chunks[start:end]
            batch_texts = [doc.page_content for doc in batch_docs]

            logger.debug(f"Processing batch {start} - {end - 1}")
            batch_embeddings = embedding_manager.generate_embedding(batch_texts, batch_size=batch_size)
            self.add_document(batch_docs, batch_embeddings)

            if torch.cuda.is_available():
                torch.cuda.empty_cache()

        logger.info("All batches inserted successfully.")

import logging

LEARNED_QA_METADATA = {
    "description": "Distilled QA pairs from verified interactions.",
    "hnsw:space": "cosine",
}


def _collection_space(collection) -> str:
    configuration = getattr(collection, "configuration", {}) or {}
    hnsw = configuration.get("hnsw") or {}
    return hnsw.get("space", "")


def _snapshot_collection(collection, batch_size: int) -> list[dict]:
    records: list[dict] = []
    total = collection.count()
    for offset in range(0, total, batch_size):
        batch = collection.get(
            limit=batch_size,
            offset=offset,
            include=["embeddings", "metadatas", "documents"],
        )
        ids = batch.get("ids") or []
        embeddings = batch.get("embeddings")
        metadatas = batch.get("metadatas")
        documents = batch.get("documents")
        for index, uid in enumerate(ids):
            records.append({
                "id": uid,
                "embedding": embeddings[index] if embeddings is not None else None,
                "metadata": metadatas[index] if metadatas is not None else None,
                "document": documents[index] if documents is not None else None,
            })
    return records


def _restore_collection(collection, records: list[dict], batch_size: int) -> None:
    for start in range(0, len(records), batch_size):
        batch = records[start:start + batch_size]
        add_kwargs = {
            "ids": [record["id"] for record in batch],
            "embeddings": [record["embedding"] for record in batch],
        }
        if all(record["metadata"] is not None for record in batch):
            add_kwargs["metadatas"] = [record["metadata"] for record in batch]
        if all(record["document"] is not None for record in batch):
            add_kwargs["documents"] = [record["document"] for record in batch]
        collection.add(**add_kwargs)


def get_or_create_learned_qa_collection(
    client: chromadb.ClientAPI,
    collection_name: str = LEARNED_COLLECTION,
    batch_size: int = 512,
):
    """Return a cosine learned-QA collection, migrating an older L2 index safely."""
    try:
        collection = client.get_collection(name=collection_name)
    except NotFoundError:
        return client.create_collection(
            name=collection_name,
            metadata=LEARNED_QA_METADATA,
        )

    if _collection_space(collection) == "cosine":
        return collection

    records = _snapshot_collection(collection, batch_size)
    backup_name = f"{collection_name}__distance_backup_{uuid.uuid4().hex[:8]}"
    original_metadata = dict(getattr(collection, "metadata", {}) or {})
    target_metadata = {**original_metadata, **LEARNED_QA_METADATA}

    logger.info(
        f"[LearnedQAStore] migrating '{collection_name}' from "
        f"{_collection_space(collection) or 'unknown'} to cosine "
        f"({len(records)} entries)."
    )

    collection.modify(name=backup_name)
    replacement = None
    try:
        replacement = client.create_collection(
            name=collection_name,
            metadata=target_metadata,
        )
        _restore_collection(replacement, records, batch_size)
        if replacement.count() != len(records):
            raise RuntimeError(
                f"learned-QA migration count mismatch: "
                f"expected {len(records)}, restored {replacement.count()}"
            )
        client.delete_collection(name=backup_name)
    except Exception:
        if replacement is not None:
            try:
                client.delete_collection(name=collection_name)
            except NotFoundError:
                pass
        collection.modify(name=collection_name)
        raise

    logger.info(
        f"[LearnedQAStore] learned_qa migration complete: "
        f"{replacement.count()} entries, cosine distance."
    )
    return replacement

_COSINE = {"hnsw:space": "cosine"}


class MemoryCollection:
    """A single ChromaDB collection, embedded and queried via EmbeddingManager."""

    def __init__(
        self,
        client: chromadb.ClientAPI,
        name: str,
        description: str,
        embedding_manager: EmbeddingManager,
    ):
        self.name = name
        self.embedding_manager = embedding_manager
        self.collection = client.get_or_create_collection(
            name=name,
            metadata={"description": description, **_COSINE},
        )
        logger.info(
            "[MemoryCollection] '%s' ready — %d entr%s.",
            name, self.collection.count(), "y" if self.collection.count() == 1 else "ies",
        )

    def add(self, uid: str, text: str, metadata: dict) -> bool:
        """Store one memory. Returns False if uid already exists (idempotent)."""
        existing = self.collection.get(ids=[uid])["ids"]
        if existing:
            logger.debug("[MemoryCollection:%s] '%s' already stored — skipping.", self.name, uid)
            return False
        embedding = self.embedding_manager.generate_embedding([text])[0]
        self.collection.add(
            ids=[uid],
            embeddings=[embedding.tolist()],
            documents=[text],
            metadatas=[metadata],
        )
        logger.info("[MemoryCollection:%s] stored '%s'.", self.name, uid)
        return True

    def search(self, query: str, k: int = 4) -> list[dict]:
        """Return up to k semantically similar memories, most similar first."""
        count = self.collection.count()
        if count == 0:
            return []
        embedding = self.embedding_manager.generate_embedding([query])[0]
        results = self.collection.query(
            query_embeddings=[embedding.tolist()],
            n_results=min(k, count),
        )
        docs = (results.get("documents") or [[]])[0]
        metas = (results.get("metadatas") or [[]])[0]
        dists = (results.get("distances") or [[]])[0]
        return [
            {"content": doc, "metadata": meta, "distance": dist}
            for doc, meta, dist in zip(docs, metas, dists)
        ]
