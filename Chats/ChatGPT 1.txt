# 🧠 What are Embeddings? (Core Idea)

Embeddings are simply:

👉 **Numerical representations (vectors) of text that capture meaning**

Instead of storing text like:

> "I love programming"

We convert it into something like:

[
[0.21, -0.55, 0.78, 0.13, \dots]
]

This vector is typically:

* 384, 512, or 768 numbers long (depending on model)

---

## 🔍 Why embeddings matter in RAG

RAG doesn’t search text using keywords.

Instead, it:

1. Converts documents → embeddings
2. Converts your query → embedding
3. Finds **similar vectors**

👉 That’s how it finds *relevant information semantically*

---

## 🧩 Example (very important)

| Text         | Meaning |
| ------------ | ------- |
| "car"        | 🚗      |
| "automobile" | 🚗      |

Even though words differ, embeddings will be **very close numerically**.

👉 That’s the magic: **semantic understanding**

---

They are created using **pretrained transformer models**, like:

* `all-MiniLM-L6-v2` (your code)

* OpenAI embedding models

code:
class RAGRetriever:
    def __init__(self, vector_store: VectorStore, embedding_manager: EmbeddingManager):
        self.vector_store = vector_store
        self.embedding_manager = embedding_manager
        
    def retrieve(self, query: str, top_k: int = 5, score_threshold: float = 0.0) -> List[Dict[str, Any]]:
        query_embedding = self.embedding_manager.generate_embedding(query)
        
        print(f"Retrieving top {top_k} documents for query: '{query}'")
        
        
        results = self.vector_store.collection.query(
            query_embeddings=[query_embedding.tolist()],
            n_results=top_k,
            include=["documents", "metadatas", "embeddings"]
        )
        
        retrieved_docs = []
        if results and "documents" in results and results["documents"][0]:
            documents = results["documents"][0]
            metadatas = results["metadatas"][0]
            distances = results["distances"][0] 
            ids = results["ids"][0]
        
        for i, (doc, meta, dist, doc_id) in enumerate(zip(documents, metadatas, distances, ids)):
            score = 1 - dist
            if score < score_threshold:
                print(f"Document {i} (ID: {doc_id}) skipped due to low score: {score:.4f}")
                continue
            
            retrieved_docs.append({
                "id": doc_id,
                "content": doc,
                "metadata": meta,
                "similarity_score": score,
                "distance": dist,
                "rank": i + 1
            })
            print(f"Document {i} (ID: {doc_id}) retrieved with score: {score:.4f}")
            
        return retrieved_docs

# Corrected version of your method

```python
class RAGRetriever:
    def __init__(self, vector_store: VectorStore, embedding_manager: EmbeddingManager):
        self.vector_store = vector_store
        self.embedding_manager = embedding_manager
        
    def retrieve(self, query: str, top_k: int = 5, score_threshold: float = 0.0):
        query_embedding = self.embedding_manager.generate_embedding(query)
        
        print(f"Retrieving top {top_k} documents for query: '{query}'")
        
        results = self.vector_store.collection.query(
            query_embeddings=[query_embedding.tolist()],
            n_results=top_k,
            include=["documents", "metadatas", "embeddings", "distances"]
        )
        
        retrieved_docs = []

        if results and "documents" in results and results["documents"] and results["documents"][0]:
            documents = results["documents"][0]
            metadatas = results["metadatas"][0]
            distances = results["distances"][0]
            ids = results["ids"][0]

            for i, (doc, meta, dist, doc_id) in enumerate(zip(documents, metadatas, distances, ids)):
                score = 1 - dist

                if score < score_threshold:
                    print(f"Document {i} (ID: {doc_id}) skipped due to low score: {score:.4f}")
                    continue
                
                retrieved_docs.append({
                    "id": doc_id,
                    "content": doc,
                    "metadata": meta,
                    "similarity_score": score,
                    "distance": dist,
                    "rank": i + 1
                })
                print(f"Document {i} (ID: {doc_id}) retrieved with score: {score:.4f}")
        
        return retrieved_docs
```

This is often used, but whether it is meaningful depends on the distance metric used by your vector DB.

For example:

* if Chroma uses cosine distance, then `1 - dist` can be a rough similarity score
* if it uses some other metric, this may not be the best interpretation

So this is okay for learning, but later you should verify what distance metric your collection uses.

## Cell 4

Replace your `EmbeddingManager` with this safer version:

```python
class EmbeddingManager:
    def __init__(self, model_name: str = "all-MiniLM-L6-v2"):
        self.model_name = model_name
        self.model = None
        self.device = "cuda" if torch.cuda.is_available() else "cpu"
        self._load_model()

    def _load_model(self):
        try:
            self.model = SentenceTransformer(self.model_name, device=self.device)
            print(
                f"Model '{self.model_name}' loaded on {self.device}. "
                f"Embedding dimension: {self.model.get_sentence_embedding_dimension()}"
            )
            if self.device == "cuda":
                print("GPU:", torch.cuda.get_device_name(0))
        except Exception as e:
            print(f"Error loading model '{self.model_name}': {e}")
            raise

    def generate_embedding(self, text, batch_size: int = 16) -> np.ndarray:
        if self.model is None:
            raise ValueError("Model not loaded.")

        try:
            embedding = self.model.encode(
                text,
                batch_size=batch_size,
                show_progress_bar=True,
                convert_to_numpy=True,
                normalize_embeddings=True,
                device=self.device
            )
            return embedding
        except Exception as e:
            print(f"Error generating embedding: {e}")
            raise

    def get_embedding_dimension(self) -> int:
        if self.model is None:
            raise ValueError("Model not loaded.")
        return self.model.get_sentence_embedding_dimension()

embedding_manager = EmbeddingManager()
```

```python
def add_documents_in_batches(pdf_chunks, embedding_manager, vector_store, batch_size=16):
    total = len(pdf_chunks)
    print(f"Adding {total} chunks in batches of {batch_size}")

    for start in range(0, total, batch_size):
        end = min(start + batch_size, total)
        batch_docs = pdf_chunks[start:end]
        batch_texts = [doc.page_content for doc in batch_docs]

        print(f"Processing batch {start} to {end - 1}")

        batch_embeddings = embedding_manager.generate_embedding(
            batch_texts,
            batch_size=batch_size
        )

        vector_store.add_document(batch_docs, batch_embeddings)

        if torch.cuda.is_available():
            torch.cuda.empty_cache()

    print("All batches inserted successfully.")

add_documents_in_batches(pdf_chunks, embedding_manager, vector_store, batch_size=16)
```

# The most important concept first

A **self-learning agent** should **not** automatically learn from every answer it gives.

That becomes dangerous very quickly because it can:

* store hallucinations,
* reinforce wrong information,
* pollute the vector database.

So the right approach is:

**self-learning = controlled memory update**

Meaning:

1. agent answers,
2. user feedback or external validation happens,
3. only then the new knowledge is saved.

That is the version you should build.

---

# How to think about the upgrade

You should convert your app in **3 stages**.

## Stage 1 — Turn RAG into an agent

Add decision-making on top of retrieval.

Instead of always doing:

1. embed query
2. retrieve docs
3. answer

the system should decide:

* Do I need retrieval?
* Do I need to rephrase the query?
* Do I need more than one retrieval pass?
* Do I need to ask a follow-up question?
* Do I need to summarize before answering?

This is the first real “agent” behavior.

### Minimal agent loop

The agent should do:

1. Receive user question
2. Decide whether to retrieve
3. Retrieve documents
4. Judge whether context is enough
5. Answer
6. Optionally store approved learning

## Stage 2 — Add memory

You need **two types of memory**.

### 1. Short-term memory

This is just session memory:

* previous user questions
* previous answers
* current conversation context

This helps the agent answer follow-up questions better.

### 2. Long-term memory

This is where “self-learning” starts:

* user-approved facts
* distilled notes
* extracted FAQs
* corrected answers
* summaries of useful interactions

This memory should be stored separately from raw source documents.

Do **not** mix:

* source documents
* learned memory
* chat history

Keep them as separate collections.

---

## Stage 3 — Add feedback-based learning

This is the actual self-learning layer.

After answering, the system should optionally ask:

* Was this answer helpful?
* Should I save this explanation?
* Is this correction valid?

Then only if validated:

* create a short clean memory note
* embed it
* store it in a separate memory collection

That is how the app becomes self-improving.
