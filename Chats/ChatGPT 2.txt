# 🧠 What these actually mean (important)

## 🔹 Chunk Size = 1000

Each document is split into pieces of ~1000 characters.

From your PDF example, you can see each `Document(...)` contains fragments like:

> "Autism spectrum disorder is a neurodevelopmental disorder..." 

So instead of embedding full PDFs, you embed smaller chunks.

### Why this matters:

* Too small → lose context
* Too large → embeddings become noisy + slow

👉 1000 is a **very standard, safe value**

---

## 🔹 Chunk Overlap = 200

Each chunk shares 200 characters with the next chunk.

### Why this matters:

* Prevents **context loss between chunks**
* Helps retrieval stay accurate

👉 200 is a **good default (20%)**

---

## 🔹 Batch Size = 16

This is how many chunks you embed at once on GPU.

### Why this matters:

* Higher batch → faster but more GPU memory
* Lower batch → safer but slower
