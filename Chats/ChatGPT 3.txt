Discuss some similarity search methods

Similarity search methods are techniques used to find data points that are “closest” or most similar to a given query. They are heavily used in AI systems, recommendation engines, Retrieval-Augmented Generation (RAG), semantic search, image retrieval, and vector databases.

Below are some important similarity search methods:

---

# 1. Exact Similarity Search

Exact search compares the query against every vector or item in the dataset.

### How it works

If there are `N` vectors, the algorithm computes similarity with all `N` vectors and returns the nearest ones.

### Common Metrics

## Cosine Similarity

Measures the angle between vectors.

\cos(\theta)=\frac{A\cdot B}{|A||B|}

* Values range from `-1` to `1`
* Common in text embeddings and LLM applications
* Focuses on direction rather than magnitude

### Use Cases

* Semantic search
* Text embeddings
* RAG systems

---

## Euclidean Distance

Measures straight-line distance between vectors.

d(p,q)=\sqrt{\sum_{i=1}^{n}(q_i-p_i)^2}

* Smaller distance means more similarity
* Sensitive to vector magnitude

### Use Cases

* Image similarity
* Clustering
* Recommendation systems

---

## Dot Product Similarity

Measures vector alignment and magnitude together.

A\cdot B=\sum_{i=1}^{n}A_iB_i

### Use Cases

* Neural retrieval systems
* Dense embedding search
* Transformer attention mechanisms

---

# 2. Approximate Nearest Neighbor (ANN) Search

When datasets become huge (thousands, millions, or billions of vectors), exact search becomes slow.

ANN methods trade a little accuracy for major speed improvements.

---

# 3. KD-Tree (K-Dimensional Tree)

A tree-based spatial partitioning method.

### Idea

* Splits data recursively by dimensions
* Reduces search space

### Advantages

* Fast for low-dimensional data
* Efficient memory usage

### Disadvantages

* Performance drops in high dimensions
* Suffers from the “curse of dimensionality”

### Best For

* 2D/3D geometric data
* Small dimensional datasets

---

# 4. Ball Tree

Groups points into hyperspheres (“balls”).

### Advantages

* Better than KD-Tree in moderately high dimensions
* Works well with distance metrics

### Use Cases

* Machine learning nearest-neighbor algorithms
* Scientific datasets

---

# 5. Locality Sensitive Hashing (LSH)

Uses hash functions so similar items fall into the same bucket.

### Key Idea

Instead of comparing everything:

* Convert vectors into hashes
* Compare only vectors in relevant buckets

### Advantages

* Very fast
* Scales well

### Disadvantages

* Approximate results
* May miss some neighbors

### Use Cases

* Large-scale document similarity
* Near-duplicate detection

---

# 6. HNSW (Hierarchical Navigable Small World)

One of the most powerful modern ANN methods used in vector databases.

### Idea

Creates layered graph structures:

* Higher layers = long-range navigation
* Lower layers = detailed local search

### Advantages

* Extremely fast
* High recall accuracy
* Excellent scalability

### Disadvantages

* Higher memory usage
* Index construction can be expensive

### Used In

* Pinecone
* Weaviate
* Qdrant
* Milvus

This is one of the best choices for modern Agentic AI and RAG systems.

---

# 7. IVF (Inverted File Index)

Clusters vectors into groups.

### Process

1. Divide vectors into clusters
2. Search only the most relevant clusters

### Advantages

* Faster than brute force
* Efficient on large datasets

### Disadvantages

* Accuracy depends on clustering quality

### Commonly Used With

* Product Quantization (PQ)
* FAISS indexing

---

# 8. Product Quantization (PQ)

Compresses vectors into compact representations.

### Advantages

* Reduces memory usage
* Enables billion-scale search

### Disadvantages

* Some precision loss

### Used In

* Meta’s FAISS

---

# 9. Graph-Based Similarity Search

Represents vectors as graph nodes connected to nearby neighbors.

### Advantages

* High retrieval quality
* Very scalable

### Examples

* HNSW
* NSW graphs

---

# 10. Hybrid Search

Combines multiple retrieval techniques.

### Example

* BM25 keyword search + vector similarity

### Why Important

Pure vector search sometimes misses:

* exact keywords
* numbers
* identifiers
* names

Hybrid search solves this problem.

### Used In

Modern RAG pipelines and AI agents.

---

# Comparison Summary

| Method        | Type        | Speed          | Accuracy  | Best For             |
| ------------- | ----------- | -------------- | --------- | -------------------- |
| Brute Force   | Exact       | Slow           | Perfect   | Small datasets       |
| KD-Tree       | ANN         | Fast           | Good      | Low dimensions       |
| Ball Tree     | ANN         | Moderate       | Good      | Medium dimensions    |
| LSH           | ANN         | Very Fast      | Moderate  | Massive datasets     |
| HNSW          | ANN         | Extremely Fast | Very High | Modern vector DBs    |
| IVF           | ANN         | Fast           | High      | Large datasets       |
| PQ            | Compression | Very Fast      | Moderate  | Billion-scale search |
| Hybrid Search | Combined    | Fast           | Very High | RAG & AI Agents      |

These three are the core mathematical methods used to measure how “similar” two vectors are. In AI systems, text, images, audio, and documents are converted into vectors (embeddings), and these methods compare them.

Let’s understand them intuitively.

---

# First: What is a Vector?

A vector is simply a list of numbers representing data.

Example:

```python
A = [1, 2, 3]
B = [2, 4, 6]
```

In embedding models:

* a sentence
* an image
* a paragraph
* a document

gets converted into vectors like:

```python
[0.12, -0.44, 0.91, ...]
```

Similarity search compares these vectors.

---

# 1. Cosine Similarity

## Main Idea

Cosine similarity measures the ANGLE between vectors.

It checks:

> “Are these vectors pointing in the same direction?”

NOT:

* how long they are
* how large their values are

---

## Formula

\cos(\theta)=\frac{A\cdot B}{|A||B|}

---

# Intuition

Imagine arrows in space.

* Same direction → very similar
* Opposite direction → very different
* Perpendicular → unrelated

---

# Value Range

| Value | Meaning                |
| ----- | ---------------------- |
| 1     | Exactly same direction |
| 0     | Unrelated              |
| -1    | Completely opposite    |

---

# Example

```python
A = [1, 2]
B = [2, 4]
```

These point in the same direction.

Cosine similarity:

```python
= 1
```

Even though:

* B is larger
* magnitudes differ

they are still considered highly similar.

---

# Why Important in AI?

In text embeddings:

* vector length often doesn't matter
* semantic direction matters

Example:

```text
"I love cats"
"I really love cats"
```

Embedding magnitudes may differ,
but meanings are almost same.

Cosine similarity handles this well.

---

# Used In

* Semantic search
* RAG systems
* Vector databases
* LLM embeddings
* Sentence transformers

Most modern RAG systems use cosine similarity.

---

# 2. Euclidean Distance

## Main Idea

Measures ACTUAL DISTANCE between vectors.

Like physical distance between two points.

---

## Formula

d(p,q)=\sqrt{\sum_{i=1}^{n}(q_i-p_i)^2}

---

# Intuition

Imagine coordinates:

```python
A = (1,1)
B = (4,5)
```

Euclidean distance calculates the straight-line distance.

Like using a ruler.

---

# Example

```python
A = [1,2]
B = [4,6]
```

Distance:

```python
sqrt((4-1)^2 + (6-2)^2)
= sqrt(9 + 16)
= sqrt(25)
= 5
```

---

# Important Property

Smaller distance = more similarity.

Unlike cosine similarity:

* magnitude matters here

---

# Example Showing Difference

```python
A = [1,1]
B = [100,100]
```

Cosine similarity:

* VERY high
* same direction

Euclidean distance:

* HUGE
* far apart

This is the key conceptual difference.

---

# Used In

* Computer vision
* Clustering
* KNN algorithms
* Recommendation systems
* Spatial data

---

# 3. Dot Product Similarity

## Main Idea

Measures:

* alignment
  AND
* magnitude

together.

---

## Formula

A\cdot B=\sum_{i=1}^{n}A_iB_i

---

# Example

```python
A = [1,2]
B = [3,4]
```

Dot product:

```python
= (1×3) + (2×4)
= 3 + 8
= 11
```

---

# Intuition

Large values happen when:

* vectors point similarly
  AND
* vectors are large

So it combines:

* direction
* strength

---

# Connection to Cosine Similarity

Cosine similarity is basically:

```text
Dot Product / Normalization
```

Cosine removes magnitude effects.

Dot product keeps them.

---

# Why Transformers Use Dot Product

Transformer attention works using dot products.

Why?

Because:

* large aligned vectors should get more attention
* magnitude can carry importance

Attention mechanism:

```text
Query ⋅ Key
```

determines relevance.

---

# Used In

* Transformer attention
* Neural retrieval
* Dense vector search
* Recommendation models

# Why Exact Search Becomes Slow

Suppose you have a vector database with:

```text
1,000,000 document embeddings
```

and a user asks a query.

The system must:

1. convert query into embedding
2. compare it against ALL 1,000,000 vectors
3. compute similarity score for each
4. sort results
5. return top-k matches

This is called:

```text
Brute Force / Exact Nearest Neighbor Search
```

because it checks every vector.

---

# Problem With Exact Search

Each comparison is mathematically expensive.

For example:

* embedding dimension = 768
* vectors = 1 million

Then:

```text
1,000,000 × 768
```

operations are needed for ONE query.

Now imagine:

* thousands of users
* real-time chat
* AI agents repeatedly retrieving

Latency becomes huge.

---

# Exact Search Guarantees Accuracy

Exact search finds the TRUE nearest vectors.

Meaning:

```text
100% correct nearest neighbors
```

But:

* very slow
* expensive
* poor scalability

---

# Approximate Nearest Neighbor (ANN)

ANN says:

> “Instead of checking EVERYTHING, intelligently search only likely regions.”

It sacrifices a tiny bit of accuracy for MASSIVE speed gains.

---

# Real-Life Analogy

Imagine finding:

> “the tallest student in a country”

---

## Exact Search

You measure:

* every student
* in every city
* individually

Perfect answer.
Very slow.

---

## ANN Search

You:

1. first identify tallest regions
2. shortlist basketball academies
3. search there first

You may miss the absolute tallest person,
but you find someone extremely close MUCH faster.

That’s ANN.

---

# Core Idea of ANN

ANN algorithms try to:

```text
Avoid comparing with every vector
```

Instead they:

* partition data
* cluster vectors
* create graphs
* hash similar vectors together

This dramatically reduces search space.

---

# Example

Suppose you have:

```text
10 million vectors
```

Exact search:

```text
compare with all 10 million
```

ANN might search only:

```text
5,000 vectors
```

while still achieving:

```text
95–99% retrieval accuracy
```

This is an enormous speedup.

---

# Tradeoff

| Method       | Speed     | Accuracy             |
| ------------ | --------- | -------------------- |
| Exact Search | Slow      | Perfect              |
| ANN          | Very Fast | Slightly Approximate |

---

Still highly relevant,

If retrieval is:

# What is BM25?

BM25 (Best Matching 25) is a traditional keyword-based ranking algorithm used in search engines to find relevant documents.

It is one of the most important retrieval algorithms in:

* search engines
* document retrieval
* hybrid RAG systems
* Elasticsearch/OpenSearch systems

Unlike vector similarity search, BM25 does NOT understand semantic meaning.

Instead, it works using:

* exact keywords
* term frequency
* document statistics

---

# Main Idea

BM25 tries to answer:

> “How relevant is this document to the query based on keyword occurrence?”

It ranks documents using:

1. how often query terms appear
2. how rare those terms are
3. document length normalization

---

# Why BM25 is Important

Vector embeddings are excellent at semantic meaning.

But they can fail at:

* exact numbers
* IDs
* names
* abbreviations
* rare technical terms
* code snippets

BM25 is excellent at those.

That’s why modern RAG systems often combine:

```text id="mjlwmu"
BM25 + Vector Search
```

called:

```text id="d6v3qz"
Hybrid Search
```

---

# Core Concepts of BM25

---

# 1. Term Frequency (TF)

Measures:

> “How many times does a word appear in a document?”

Example:

Query:

```text id="kjqr2u"
"machine learning"
```

Document A:

```text id="4ogmjh"
machine learning machine learning machine learning
```

Document B:

```text id="9l8v62"
machine learning
```

Document A gets higher score.

Because terms appear more frequently.

---

# But TF Alone is Bad

Common words like:

* the
* is
* and

would dominate scores.

So BM25 adds another concept.

---

# 2. Inverse Document Frequency (IDF)

Measures:

> “How rare is this word across all documents?”

Rare words are more informative.

---

## Example

Suppose:

```text id="8yyl5l"
"the"
```

appears in almost every document.

Not useful.

But:

```text id="vk44ff"
"transformer"
```

appears in few documents.

Very informative.

BM25 boosts rare terms.

---

# IDF Formula

IDF(q_i)=\log\left(\frac{N-n(q_i)+0.5}{n(q_i)+0.5}+1\right)

Where:

* `N` = total documents
* `n(q_i)` = documents containing term

---

# 3. Document Length Normalization

Long documents naturally contain more words.

Without normalization:

* large documents always win

BM25 penalizes overly long documents.

---

# BM25 Formula

BM25(D,Q)=\sum_{i=1}^{n}IDF(q_i)\cdot\frac{f(q_i,D)(k_1+1)}{f(q_i,D)+k_1\left(1-b+b\cdot\frac{|D|}{avgdl}\right)}

Looks scary,
but conceptually it combines:

* keyword frequency
* rarity
* document length adjustment

---

# Intuitive Example

Suppose user searches:

```text id="q6gf3d"
"llama 3.1 8b"
```

Documents:

---

## Document A

```text id="0wmp6g"
This paper discusses llama 3.1 8b architecture.
```

---

## Document B

```text id="r5e5v9"
This paper discusses large language models generally.
```

---

# BM25 Result

Document A wins strongly because:

* exact terms match
* rare keywords match

Even if embeddings might think both are similar.

Does opus 4.7 uses more tokens than the rest of the models in this?
Yes — generally, Claude Opus 4.7 tends to consume more tokens in practice compared to lighter models like Sonnet or Haiku, but there are two different things people mean by “uses more tokens”:

1. Context Window / Token Capacity

Opus models usually support very large context windows (often similar to Sonnet in max capacity), so they can handle lots of tokens.

That does not automatically mean they charge or consume more tokens per message.

2. Actual Token Usage During Reasoning

This is where Opus 4.7 differs.

Because it is a larger and more capable reasoning model:

It tends to generate:
longer outputs
more detailed chain-of-thought style reasoning
more verbose planning
Adaptive thinking (enabled in your screenshot) can further increase internal reasoning/computation.

So for the same task, Opus may:

produce more output tokens
spend more hidden reasoning compute
therefore cost more and feel slower

compared to:
