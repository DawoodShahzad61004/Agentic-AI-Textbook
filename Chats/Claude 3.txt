Self-Learning Design
The mechanism works in 3 layers:

1. Interaction Memory (feedback_store.py)
Every Q&A interaction is logged with: query, answer, sources used, and implicit quality signal (was check_answer_quality OK or INSUFFICIENT?). Stored as a JSON ledger.

2. Synthetic QA Distillation (self_learner.py)
After every N interactions, a distillation job runs:

Takes the last N interactions where quality was OK
Uses those verified (query → answer → source chunks) triples to generate synthetic Q&A pairs via the LLM
Embeds those synthetic pairs and adds them back into ChromaDB as a new collection layer (learned_qa)
3. Hybrid Retrieval (retriever.py update)
The retriever queries both the original documents collection and the learned_qa collection, then merges and re-ranks results. This means past good answers become first-class retrieval targets — reducing hallucination on repeated/similar queries.

How accuracy improves over time
Interaction 1–4:  queries hit only original docs
Interaction 5:    distillation fires → 5-15 QA pairs enter learned_qa
Interaction 6+:   similar future queries now surface distilled answers
                  as top results (pre-verified, source-grounded)
Interaction 10:   another distillation round — compounding
The key insight: distilled pairs embed as "Q: … A: …" text, which scores highly against future queries phrased similarly — effectively turning your best past answers into a fast-retrieval cache that bypasses re-reasoning from scratch.

Two bugs fixed across two files. Here's exactly what was wrong and why:

Bug 1 — tools.py: context exposed in the LLM schema

The check_answer_quality schema listed context as a required parameter, so Groq's LLM tried to fill it. It fabricated a value (a concatenation of query strings), which then failed Groq's own tool-call validation and returned the 400 tool_use_failed error. The fix: remove context from the schema entirely. The LLM now only sends answer; your agent loop injects context server-side before calling the function. The LLM never needs to know context exists.

Bug 2 — agent_query.py: last_context was overwritten on each retrieval

When the agent called retrieve_documents three times, last_context was reassigned each time, so check_answer_quality only ever saw the final retrieval's results. Changed last_context (single string, overwritten) to accumulated_context (a list that appends), and the quality check now joins all retrieval results with a separator before injecting them.
