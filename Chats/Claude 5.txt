The collision: The acronym ASD is overloaded. The PDF and JSON files use it for Autism Spectrum Disorder and use that abbreviation extensively. The Adjustable Speed Drive file uses only the long form — never "ASD". So if someone asks "What is ASD?" the retriever will only find autism content, even though Adjustable Speed Drive is a perfectly valid expansion. That's the trap.

The trick is to find a query phrasing that:

Looks ambiguous to a human reader (could mean either)
But embeds semantically close to the ASD/autism content (so the retriever pulls only autism chunks)
Which produces an answer that's confidently wrong relative to what the user actually wanted
A bare "What is ASD?" is too obviously medical-leaning once retrieval kicks in. We want something that, given the corpus, will retrieve autism content even though the user meant the engineering one.

Recommended confusing query

"Components and working principles" is engineering phrasing — it's how the Adjustable Speed Drive document is literally structured (it has sections titled "Components of an Adjustable Speed Drive" and "Working Principle of Adjustable Speed Drives"). The retriever will pull autism chunks (where "ASD" appears literally and frequently). The LLM will then answer about social communication deficits, repetitive behaviors, DSM-5, etc. — which is wrong for the asked intent.
