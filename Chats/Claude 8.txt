Looking at your `_build_system_prompt` function and `_BASE_SYSTEM_PROMPT`, here's the refactor.

## The current structure

Your `_BASE_SYSTEM_PROMPT` mixes everything together:
1. Role + answer-only rule
2. HARD LIMITS
3. TOOLS
4. PROCESS

Then `_build_system_prompt` appends BLOCKED VARIANTS and USER-FLAGGED PRIOR FAILURE *after* PROCESS. So the model reads: rules → process → contextual junk → user message. The PROCESS list gets pushed away from the user query as the prompt grows.

## The fix

Split `_BASE_SYSTEM_PROMPT` into two halves: the *role/rules* go first, the *process* comes last. The thumbdown and blocked-variant context gets sandwiched between them.

Replace your current `_BASE_SYSTEM_PROMPT` with these two:

```python
_ROLE_AND_RULES = """You are a research assistant. Answer ONLY from retrieved chunks — never from memory.

HARD LIMITS (enforced by the system — do not test them):
- retrieve_documents: max 5 calls total. Stop at 3 if results are poor.
- Never repeat a query already tried. Never generate two queries with identical words.
- If the knowledge base has no answer after 3 tries, say: "The knowledge base does not contain information about [topic]."
- Never fabricate facts.

TOOLS:
- retrieve_documents(query, top_k): searches the knowledge base
- check_answer_quality(answer): validates your answer is grounded
"""

_PROCESS_INSTRUCTIONS = """PROCESS (follow in this exact order — do NOT batch tool calls):
1. FIRST, call retrieve_documents 2–3 times with SHORT, semantically different queries.
   Wait for results before doing anything else. Do NOT call check_answer_quality yet.
   GOOD: short noun-phrase queries from different angles of the topic.
   BAD:  rephrasings of the same angle ("what causes X", "X causes", "causes of X") — forbidden.
2. If results are insufficient → one more rephrased query, then stop retrieving.
3. THEN write a synthesized answer that:
   - Directly addresses the user's question first
   - Combines information from multiple chunks into coherent prose
   - Does NOT copy chunk text verbatim — rephrase and integrate
   - Includes only chunks relevant to the question (ignore off-topic chunks even if retrieved)
   - Cites sources inline as [Source: filename]
4. ONLY AFTER you have written your draft, call check_answer_quality(answer=<your draft>).
5. Return final answer.
"""
```

Then rewrite `_build_system_prompt` to assemble role → context → process:

```python
def _build_system_prompt(
    blocked_variants: list[str],
    prior_thumbdowns: list[dict] | None = None,
) -> str:
    parts = [_ROLE_AND_RULES]

    if blocked_variants:
        lines = "\n".join(f'  - "{v}"' for v in blocked_variants)
        parts.append(
            f"BLOCKED QUERY VARIANTS — These exact phrasings retrieved 0 useful chunks"
            f" the last time this question was asked. Do NOT reuse them under any"
            f" circumstances. Generate different, semantically distinct reformulations:\n{lines}"
        )

    if prior_thumbdowns:
        td_block = (
            "USER-FLAGGED PRIOR FAILURE — This same question (or a near-identical one)"
            " was asked before and the user explicitly marked the answer as bad. Below is"
            " what went wrong last time, including the exact query reformulations that were"
            " tried and the chunks they retrieved. Use this to:\n"
            "  1. AVOID re-using the same query reformulations — they led to a bad answer.\n"
            "  2. AVOID grounding your answer in the same chunks unless you can clearly"
            " interpret them differently.\n"
            "  3. Try genuinely different angles, vocabulary, and sub-topics.\n"
        )
        for i, td in enumerate(prior_thumbdowns, start=1):
            td_block += f"\n--- Prior failure #{i} ---\n"
            td_block += f"Original query : {td.get('original_query', '')}\n"
            ufb = td.get("user_feedback", "")
            if ufb:
                td_block += f"User feedback  : {ufb}\n"
            bad_ans = td.get("bad_answer", "")
            if bad_ans:
                snippet = bad_ans[:300] + ("..." if len(bad_ans) > 300 else "")
                td_block += f"Bad answer was : {snippet}\n"
            variants = td.get("variants", []) or []
            if variants:
                td_block += "Reformulations that were tried (DO NOT REUSE):\n"
                for v in variants:
                    td_block += f"  - \"{v.get('query', '')}\"\n"
                    chunks = v.get("chunks", []) or []
                    if chunks:
                        for c in chunks[:2]:
                            content = (c.get("content") or "").replace("\n", " ")
                            preview = content[:200] + ("..." if len(content) > 200 else "")
                            td_block += f"      retrieved [{c.get('source', '?')}]: {preview}\n"
        parts.append(td_block)

    # PROCESS goes LAST — closest to the user message
    parts.append(_PROCESS_INSTRUCTIONS)

    return "\n\n".join(parts)
```

## What changed and why

**Three things, in order of importance:**

1. **Process instructions moved to the end.** When the system prompt grows from ~700 tokens (run 1) to ~1,800 tokens (run 3), the PROCESS list is now the last ~250 tokens before the user message instead of being buried in the middle. Recency bias in transformer attention means the last instructions get the most weight on the next token decision — which is the tool-call decision.

2. **Strengthened the "do NOT batch" instruction.** The header now says `PROCESS (follow in this exact order — do NOT batch tool calls)` and step 1 explicitly says "Wait for results before doing anything else. Do NOT call check_answer_quality yet." Step 4 says "ONLY AFTER you have written your draft." This directly targets the failure mode you saw in run 3 iteration 1, where the model fired all 4 tool calls simultaneously including `check_answer_quality` with a fabricated answer.

3. **Used `\n\n`-joined sections instead of inline appending.** Cleaner section boundaries help the model recognize where one block of instructions ends and another begins. Tiny detail, but free.

## What this won't fix

This won't make the model start *avoiding* the blocked variants — that's the soft-prompt failure I called out before, and moving sections around doesn't address it. The fix for that is filtering at the tool layer, not in the prompt. But for the "all tool calls at once" regression, this prompt restructuring is the cheapest first attempt.

Good call — Contextual Prompting fits well here. Right now your prompt tells the model *what to do* but never tells it *what kind of knowledge base it's working with*. A model that knows it's searching medical PDFs will pick different query angles than one that thinks it's searching code docs.


## Why each piece earns its spot

- **"vector store of chunked documents... PDFs, Word docs, CSVs, HTML, JSON"** — tells the model the corpus is heterogeneous, so a CSV-style query (`"patient_id 4421"`) and a prose-style query (`"symptoms of condition X"`) are both valid shapes depending on the question.
- **"~1000 chars with 200-char overlap"** — primes the model to expect partial information per chunk and to retrieve broadly rather than expecting one perfect hit.
- **"all-MiniLM-L6-v2... cosine similarity"** — subtle but useful: this model rewards semantic paraphrase over keyword matching, which reinforces your "semantically different queries" rule in `_PROCESS_INSTRUCTIONS`.
- **"`learned_qa` collection... treat those as equally valid sources"** — your `retriever.py` already merges results from both collections, but the LLM doesn't know that. Without this line, it might distrust a chunk sourced from `learned_qa` as "second-hand."
- **"fragmentary, mid-sentence, or contain table/OCR artifacts"** — your `UnstructuredLoader` + `pdf2image` pipeline produces exactly this kind of noisy output. Telling the model to expect it discourages premature "the chunk is incomplete, I can't answer" refusals.

- **"Plain prose... No headings, no bullet lists"** — locks the shape so the model can't fall back to "let me organize this with sections" filler.
- **"Citations appear ONLY inline... Never as a trailing list"** — directly targets the failure mode from your last log. The 130+ `[Source: Adjustable Speed Drive.txt]` lines were a trailing list. This forbids it explicitly.
- **"Max 400 words. Stop when the question is answered"** — your `LLM_MAX_TOKENS=2048` lets the model run away to ~1500 words. Giving it a target *and* a stop condition prevents the runaway loop.
- **"Do not repeat the same sentence or citation twice"** — the after-run's answer literally repeats whole paragraphs (lines 415-427 vs. 433). This kills that pattern.
