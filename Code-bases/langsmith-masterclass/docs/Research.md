## 1. LangSmith Masterclass — Course Transcript (Observability, Tracing, and LLMOps)

| Field | Detail |
|---|---|
| **Topic** | Cleaned English conversion of a Hindi/Hinglish YouTube transcript ("LangSmith Masterclass") covering why LLM observability is needed, LangSmith's core concepts, and its feature surface beyond tracing — read to understand the intent behind this project's scripts and the reasoning for the `3_rag_v1` → `v4` progression. |
| **Date** | 2026-07-09 |
| **Findings** | Three motivating scenarios for observability: (1) a resume/cover-letter LLM workflow that silently got 5x slower after a code change caused an unbounded Google Drive scan — undiagnosable without per-stage latency; (2) a research-agent whose cost spiked per-report after a prompt tweak ("keep generating until excellent") caused unbounded self-retry loops with no exceptions thrown; (3) a company RAG chatbot that hallucinated policy answers, where the failure could be in the retriever (wrong chunks) or the generator (ignoring context) — indistinguishable without seeing retrieved docs and the final prompt. Core vocabulary: **Project** = the whole app, **Trace** = one end-to-end execution, **Run** = one component execution inside a trace. LangSmith traces LangChain runnables automatically, but plain Python functions (PDF load, chunk, embed) need the `langsmith.traceable` decorator to show up — this is exactly the gap `3_rag_v1.py` has and `3_rag_v2.py`/`3_rag_v3.py` close. The transcript's own RAG demo hits the same latency problem `3_rag_v4.py` fixes: re-embedding the same PDF on every run: the fix shown is to persist and reuse a FAISS index and only rebuild on file/parameter changes — `3_rag_v4.py`'s SHA-256-fingerprint cache key is a direct implementation of this pattern. Beyond tracing, LangSmith also covers: monitoring/alerting (aggregate latency/cost/error-rate across traces, threshold alerts), evaluation (LLM-as-judge, semantic similarity, custom Python evaluators, online/offline), prompt experimentation (A/B testing prompts against a dataset, a prompt playground, prompt versioning via LangChain Hub), dataset creation/annotation (building gold-standard datasets, labeling queues), user feedback capture (thumbs up/down tied to a specific trace), and team collaboration (shareable trace links, shared dashboards). None of these five are exercised by any script in this project yet — everything here is tracing-only. |
| **Conclusion** | No code changed as a result of this read — it's the reference material explaining why the project is structured as incremental RAG versions (`v1` plain → `v2` traceable setup steps → `v3` single root trace → `v4` cached index) and why `@traceable` shows up on plain functions in `3_rag_v2.py` onward. Filed for later: monitoring, evaluation, prompt experimentation, dataset/annotation, and feedback-capture are course topics not yet reflected in any script — candidates for a future numbered demo file if the course is followed further. |
