#### 2026-07-08 — venv Setup; `3_rag_v1.py` Migrated From OpenAI Embeddings to HF-Router Embeddings (Local Chat Server Has No Embeddings Endpoint)

* Set up a project virtual environment. `python3 -m venv myenv` / `python3.11 -m venv myenv` both failed — no real Python was on `PATH` (Windows Store alias redirect) and no 3.11 runtime was registered with the `py` launcher. `py --list` / `py -0` showed only Python 3.14.3 and 3.12.10 installed; chose **3.12** over the newer 3.14 for broader LangChain/LangSmith package compatibility (ADR-002). A `.venv` was in place by the time script edits began.
* Asked to point `3_rag_v1.py`'s embeddings call at the local server's own API key/base instead of a hardcoded/default OpenAI key. Read `3_rag_v1.py` and `llm_setup.py` — confirmed the project already had a `CUSTOM_API_BASE`/`CUSTOM_API_KEY` env-var pattern for the local chat LLM. Edited `3_rag_v1.py`'s `OpenAIEmbeddings` construction to use `CUSTOM_API_BASE`/`CUSTOM_API_KEY`, with a configurable `CUSTOM_EMBEDDING_MODEL_NAME` env var.
* Ran the script — crashed with `openai.NotFoundError: Error code: 404 - {'detail': 'Not Found'}` inside `FAISS.from_documents(...) → embed_documents(...)`.
* Diagnosed the local server directly: `curl` against `/v1/models` (404), the bare root (404), and `/openapi.json` — which revealed the server ("TGI Proxy") only implements `/v1/chat/completions`, `/v1/completions`, and `/health`. **No embeddings endpoint exists on this server at all**, so no amount of API-key/model-name tweaking could have worked. Recorded as BUG-001.
* Chose Hugging Face's Inference router as the embeddings source. Confirmed `langchain_huggingface`/`huggingface_hub` were not yet installed. Probed the router directly with the project's existing `HF_TOKEN`: a guessed `/embeddings` REST path 404'd; the `feature-extraction` pipeline endpoint (`https://router.huggingface.co/hf-inference/models/sentence-transformers/all-MiniLM-L6-v2/pipeline/feature-extraction`) returned `200` with a real embedding vector.
* Installed `langchain-huggingface` — first attempt pulled in `langchain-core==1.4.8`, breaking the existing `langchain`/`langchain-community`/`langchain-openai` pins (all require `langchain-core<1.0.0`). Re-pinning `langchain-core` back down then made the newly-installed `langchain-huggingface==1.2.2` (needs `langchain-core>=1.2`) the incompatible package. Resolved by installing `langchain-huggingface<1.0.0` instead (landed on `0.3.1`), compatible with `langchain-core==0.3.86` and everything else pinned — no more resolver errors.
* Introspected `HuggingFaceEndpointEmbeddings`'s Pydantic fields (`model`, `provider`, `repo_id`, `task`, `huggingfacehub_api_token`, ...) via `model_fields` to confirm constructor kwargs, then smoke-tested it standalone: `embed_documents(["hello world", "another sentence"])` → 2 vectors × 384 dims — confirmed `sentence-transformers/all-MiniLM-L6-v2` works end-to-end via the HF router.
* Rewrote `3_rag_v1.py`'s embeddings block: `OpenAIEmbeddings` → `HuggingFaceEndpointEmbeddings(model=..., provider="hf-inference", huggingfacehub_api_token=HF_TOKEN)`, model name overridable via `HF_EMBEDDING_MODEL_NAME`. The local TGI chat model in `llm_setup.py` was left untouched.
* Ran the full script end-to-end against `islr.pdf` (*Introduction to Statistical Learning*) with the question "What is this document about?" — got a correct, grounded answer describing the textbook's subject, permissions, and required datasets. Confirms the full chain (PDF load → chunk → HF-router embed → FAISS index → local-TGI-chat answer) works.
* Tracked in: `3_rag_v1.py`; new `.venv` (Python 3.12); `langchain-huggingface==0.3.1` added as a dependency; new Bugs.md BUG-001; new Decisions.md ADR-001, ADR-002.

#### 2026-07-09 — Docs Relocated to `docs/`; OpenAI Dependency Removed From `3_rag_v4.py`, `4_agent.py`, `5_langgraph.py`

* Asked to check whether `docs/`'s tracking files needed updates after the user made small changes to `llm_setup.py`, `.env`, and `.gitignore`. Found the tracking files had been moved into a new `docs/` folder, `llm_setup.py` trimmed down to a single `llm` client (removing `llm_tool`/`judge_llm`/`json_fix_llm`/commented `ChatGroq`), `.gitignore` trimmed (dropping the Graphify/Claude section and the rule that had excluded the five tracking files — recorded as ADR-004), and `.env` trimmed to `CUSTOM_API_*` + `LANGCHAIN_*` only.
* Diffed the trimmed `.env` against what the codebase actually needs: `3_rag_v1`–`v3` require `HF_TOKEN` (removed in the trim), and `3_rag_v4.py`/`4_agent.py`/`5_langgraph.py` implicitly require `OPENAI_API_KEY` (also removed) via bare `ChatOpenAI()`/`OpenAIEmbeddings()`. Flagged this to the user via a clarifying question rather than assuming intent.
* User confirmed: dropping `HF_TOKEN` was a mistake (reverted it back into `.env` themselves), the rest of the `.env` trim was intentional, and their OpenAI API key is not working — asked for `3_rag_v4.py`/`4_agent.py`/`5_langgraph.py` to be converted from OpenAI-dependent (embeddings + chat) onto the custom/local API, matching `3_rag_v1`–`v3`.
* Migrated `3_rag_v4.py`: `OpenAIEmbeddings` → `HuggingFaceEndpointEmbeddings` (default `sentence-transformers/all-MiniLM-L6-v2`, same pattern as v1–v3) in both `build_vectorstore` and `load_index_run`; removed the local `ChatOpenAI(model="gpt-4o-mini")` in favor of importing `llm` from `llm_setup`; updated the `embed_model_name` defaults accordingly.
* Migrated `4_agent.py`: bare `ChatOpenAI()` → `llm` from `llm_setup`.
* Migrated `5_langgraph.py`: bare `ChatOpenAI(model="gpt-4o-mini")` → `llm` from `llm_setup`. Discovered along the way that `with_structured_output` doesn't work against the local TGI Proxy — tested `method="function_calling"` (model produces the right values, but LangChain rejects the response because the proxy returns tool-call `arguments` as a dict instead of a JSON string) and `method="json_mode"` (500s), both confirmed via standalone scripts. Filed as BUG-002. Fixed by replacing `with_structured_output` with a prompt + `PydanticOutputParser` helper (`evaluate_dimension()`), verified standalone before wiring in.
* Cleaned up dead `OpenAIEmbeddings`/`ChatOpenAI` imports left in `3_rag_v2.py`/`3_rag_v3.py` from an earlier version, per the user's "clean these inconsistencies" instruction.
* Byte-compiled all five touched scripts (`py_compile`) and ran `3_rag_v4.py`, `4_agent.py`, and `5_langgraph.py` end-to-end against the local server. `3_rag_v4.py` and `5_langgraph.py` produced correct, grounded output. `4_agent.py`'s ReAct loop (Thought/Action/Observation) worked correctly against the local model, but the run itself failed because the hardcoded weatherstack API key has hit its monthly usage cap, causing the agent to loop until `max_iterations` — unrelated to this migration, filed as BUG-003 (open).
* Updated `Architecture.md` (high-level diagram, `llm_setup.py`/`3_rag_v4.py`/`4_agent.py`/`5_langgraph.py` module entries, technology stack table, new changelog entry), `Decisions.md` (new ADR-003 for the OpenAI-removal migration, new ADR-004 for the `docs/` relocation), and `Bugs.md` (new BUG-002, new BUG-003).
